## MetricFlow 0.213.0 - September 10, 2026

### Features

- Add support for the Vertica engine ([#2082](https://github.com/dbt-labs/metricflow/issues/2082))
- Add optional `datatype` field to `Dimension` and `Metric` in metricflow-semantic-interfaces, enabling downstream consumers (e.g. the Ossie converter) to preserve specific data types instead of the coarse DimensionType bucket ([#2121](https://github.com/dbt-labs/metricflow/issues/2121))
- The Ossie converter now reads and writes the `datatype` field on `Field`/`Metric`, preserving Ossie's specific data type through an Ossie -> MetricFlow -> Ossie round trip instead of collapsing it into the coarse DimensionType bucket ([#2122](https://github.com/dbt-labs/metricflow/issues/2122))

### Fixes

- Stop the sub-query reducer inlining non-deterministic expressions, which made a conversion metric overcount when queried with its conversion input metric ([#2111](https://github.com/dbt-labs/metricflow/issues/2111))
- Apply the filter on a conversion metric's base_metric/base_measure input, which was previously silently dropped during dataflow plan construction ([#2119](https://github.com/dbt-labs/metricflow/issues/2119))

### Under the Hood

- Remove Python 3.13 in CI ([#2116](https://github.com/dbt-labs/metricflow/issues/2116))
- Update test snapshot error messages ([#2117](https://github.com/dbt-labs/metricflow/issues/2117))
- Add engine option to snapshot generation scripts ([#2118](https://github.com/dbt-labs/metricflow/issues/2118))

### Security

- Sandbox Jinja rendering of where-filter templates (`where_sql_template`) to close a Server-Side Template Injection vector that allowed arbitrary code execution ([#2134](https://github.com/dbt-labs/metricflow/issues/2134))
